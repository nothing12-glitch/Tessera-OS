# TesseraOS

Вільна (Apache-2.0) мобільна операційна система на базі Android для телефонів та
віртуальних машин. TesseraOS — це дистрибутив: власний UI-шар, оформлений за
Material Design 3, поверх стабільної бази LineageOS 22.x (Android 15).

**Сторінка проєкту з живим макетом інтерфейсу:**
<https://nothing12-glitch.github.io/Tessera-OS/> — публічно, без реєстрації.
Той самий файл [site/index.html](site/index.html) працює й локально: відкрий його
у браузері, він не потребує сервера чи інтернету.

> **Чому не «з нуля».** Android — це AOSP: мільйони рядків кода, роки роботи
> команд Google. Жоден проєкт не створює ядро й системні сервіси сам — він
> бере вільну базу і додає свій шар: тему, додатки, політики, оновлення.
> TesseraOS робить те саме, легально і з відкритим кодом.

## Що в проєкті

| Шар | Реалізація |
|---|---|
| Ядро, HAL, системні сервіси | LineageOS 22.x (Android 15) |
| Material Design 3 | RRO-оверлеї в `overlay/themes/` |
| Геометрія (сітка лаунчера 5×6, док) | build-time підміни файлів у `overlay-packages/` |
| Застосунки й домашній екран | **дає база** (LineageOS 22.2: Trebuchet, «Телефон», «Повідомлення», «Камера», «Файли», годинник, калькулятор). З власного в образі рівно два модулі — майстер першого запуску (`apps/welcome`, привілейований `priv-app` без іконки) і «Світловий край» (`apps/halo`, індикатор-оверлей). Чому так — §«Чому наших застосунків майже немає» нижче; реєстр модулів — `build/scripts/apps.list` |
| Google-сервіси | не входить у образ; профіль встановлення в `config/gapps/` |
| Ціль першого релізу | x86_64 Android VM (AVD / qemu) |
| Збірка | `build/` + GitHub Actions |

### Чому наших застосунків майже немає

Тут були дві події одного дня, і без них рядок у реєстрі виглядає як
повернення старого.

2026-10-25. Сім власних застосунків (лаунчер, калькулятор, «Файли», годинник,
«Телефон», «Повідомлення», «Камера») було зібрано, поставлено на живий
емулятор Android 15 і перевірено на ньому. Після перевірки користувач проєкту
вирішив: **«Прибрати наш лаунчер зовсім»** і **«Прибрати всі наші»**
застосунки — користуватися системними.

Того ж дня з'явилася вимога, якої в базі просто немає: **«екран запуску, коли
ти встановив систему, то вискакує на весь екран «Вітаємо у Tessera OS!», далі
користувач додає свій Google Account»**. Це не «ще одна наша програма замість
стокової», а те, чого система не дає взагалі, — тому в образі повернувся
перший виняток: `apps/welcome`. Того ж дня вимогу уточнила сама людина:
«це має бути вітання як в PixelOS, і воно не має бути повноцінним додатком».
Тому це не застосунок з іконкою, а **майстер першого запуску**: `priv-app` у
`system_ext`, жодного `LAUNCHER`-фільтра, і він пише системні прапорці
`device_provisioned` / `user_setup_complete` і перемикач теми всього телефону.

Тому продукт такий: **LineageOS 22.2 + Material Design 3** (три RRO-оверлеї,
сітка лаунчера 5×6) **+ вітальня першого запуску** + **світловий край на
сповіщення** + документація й установчі скрипти.

Другий виняток з того ж правила з'явився того ж дня: користувач попросив
додати в образ цікавий концепт із новин. Вибір упав на **Pixel Glow** з
Android 17 — телефон світить на сповіщення діодами під задньою панеллю. У
LineageOS 22.2 програмного замінника немає взагалі: пункт «Індикатор»
показується лише тоді, коли залізо має діод, а на x86_64-емуляторі діода нема
за означенням. Тому `apps/halo` («Світловий край») — це та сама функція,
намальована по периметру скла, а не чергова наша програма замість стокової.

Що прибрано, а що — ні:

- прибрано з образу: `PRODUCT_PACKAGES` не містить ані лаунчера, ані шести
  програм, стокові Dialer і `messaging` навпаки повернуті (фільтр, який їх
  прибирав, прибрано);
- лишається в образі: `TesseraWelcome` — майстер першого запуску. Він уже робить
  те, чого не робив: перемикає тему всього телефону й піднімає
  `device_provisioned` / `user_setup_complete` (перевірено наживо — значення
  змінює застосунок, а не adb). Чого він досі НЕ робить: не перекриває майстра
  бази, бо не звірено, яким механізмом LineageOS 22.2 заводить свій мастер; і
  дозвіл на тестовому образі видано через `adb install -g`, а не через
  `priv-app` + дозвільний список. Що саме перевірено, а що ні —
  `apps/welcome/README.md`;
- лишається в образі: `TesseraHalo` — світловий край по периметру екрана на
  сповіщення. Теж робить менше, ніж звучить: не світить при вимкненому екрані,
  не замінює діод на задній панелі й не працює, доки людина не видасть два
  дозволи (поверх інших вікон і доступ до сповіщень). Усі три візерунки й
  життєвий цикл вікна перевірені наживо на Android 15 — `apps/halo/README.md`;
- НЕ видалено: код у `apps/`, історія git і вже опублікований пакунок
  [v15.22.2.2](https://github.com/nothing12-glitch/Tessera-OS/releases) із
  сімома APK лишаються як були; чинний найновіший опублікований пакунок —
  `v15.22.2.3`, у ньому три RRO-оверлеї теми й нуль APK (вітальня вийде
  наступним пакунком, бо на момент тієї віхи її ще не існувало);
- повернути будь-який інший застосунок — два кроки: розкоментувати рядок у
  `build/scripts/apps.list` і додати модуль у `build/tessera.mk`. Обидва кроки
  статично перевіряє `build/scripts/check-app-integration.sh`, тож варіант
  «у образі є, а CI про нього не знає» знову неможливий.

## Швидкий старт

Системна вимога для збірки ROM — **Linux**. На Windows і macOS збірка
неможлива (AOSP build system не працює нативно); використовуй WSL2/Docker
або окремий білд-бокс — реалістично 400+ ГБ місця і 16–32 ГБ RAM
(числа з документації LineageOS, див. [docs/BUILD.md](docs/BUILD.md)).

```bash
# 1. Підготувати середовище (Ubuntu 22.04/24.04, Debian 12)
build/scripts/bootstrap.sh

# 2. Синхронізувати джерела: база LineageOS 22.2 + наш шар через local_manifests
build/scripts/new-tree.sh lineage-22.2

# 3. Статична перевірка, що всі наші посилання на базу існують
build/scripts/check-build-refs.sh --tree .

# 4. Зібрати образ для емулятора (in out/target/product/emu64x)
build/scripts/build-emulator.sh

# 5. Запустити
build/scripts/run-avd.sh
```

Деталі: [docs/BUILD.md](docs/BUILD.md), [docs/EMULATOR.md](docs/EMULATOR.md).

### Якщо лінукс-білдбоксу немає

Повний образ збирається тільки на Linux. Все решти достатньо для того, щоб
**побачити TesseraOS у своїй віртуальній машині просто зараз**: пакунок теми
MD3 (три RRO-оверлеї) поверх наявного образу Android 13+ ставиться одним
скриптом — `build/scripts/install-on-vm.sh` (Linux/macOS/Git Bash) або
`install-on-vm.ps1` (Windows). Він читає той самий `build/scripts/apps.list`,
що й CI, тому закритий реєстр для нього означає «ставимо лише тему». Три шляхи,
їхні вимоги й чесні обмеження (чому це ще не ISO для VirtualBox) — в
[docs/VM-INSTALL.md](docs/VM-INSTALL.md).

Скільки заліза насправді потрібно — і чому «старий телефон» із опитування не
виходить — виміряно та записано в [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

## Google Play (GApps)

TesseraOS **не** постачається з пропрієтарними застосунками Google і не
проходить сертифікацію GMS. Це не примха, а юридична рамка: Google видає
ліцензію виробнику пристрою після CTS, тому ROM-проєкт не може легально
вшити Play Store у свій образ.

Користувач має два легальні шляхи:

1. **microG** — вільна реалізація Push/Location/Auth, працює без сертифікатів.
   У нашому образі його **немає**: в маніфесті бази LineageOS проєктів microG і
   GmsCore немає, тому рядок `PRODUCT_PACKAGES += microG` брехав би. Ставлять
   самі — APK із F-Droid/Aurora або `local_manifests` від lineage.microg.org на
   білд-боксі.
2. **GApps-пакет від вендора** (MindTheGApps) — користувач ставить сам,
   приймаючи умови Google. Скрипт `build/scripts/package-gapps.sh`
   збирає для нього коректний профіль і zip.

Повне пояснення й таблиця сумісності: [docs/GAPPS.md](docs/GAPPS.md).

## Material Design 3

Оверлеї — це RRO-пакети (`overlay/themes/`), які підмінюють ресурси framework
і Settings без форку AOSP: форма adaptive-іконок (`config_useRoundIcon`,
`config_icon_mask`) і fallback-палітра DeviceDefault. Тональні поверхні,
радіуси 12/16/28 dp й типографіка Roboto Flex — це рівень застосунків
(Compose + Material 3), у framework таких атрибутів немає; детальніше в
[docs/THEME-MD3.md](docs/THEME-MD3.md). Отож чесно: від 2026-10-25, коли власні
застосунки пішли з продукту (§«Чому наших застосунків майже немає»), TesseraOS — це
MD3 на рівні ресурсів системи та форми іконок, а не Material You в
інтерфейсі застосунків — той дає база й застосунки, які поставить користувач.
Єдині наші модулі в образі — майстер першого запуску `apps/welcome` і край
`apps/halo`,
і вони теж нічого системного не замінюють: перша стає на порожнє місце екрана
першого запуску, другий малює те, чого база не дає ніде.

Пакети збираються на звичайному GitHub-раннері, а перед збіркою CI перевіряє
кожне ім'я ресурсу проти дерева бази — `build/scripts/check-overlay-names.sh`.
Це не формальність: aapt2 не скаржиться на невідому назву, тож «зелений»
оверлей без такої перевірки може бути цілком інертним.

Базовий стиль інтерфейсу — **stock-подібний**: динамічна палітра Material You
від шпалер, круглі adaptive-іконки, стартова сітка 5×6 із 5-слотовим доком,
карткові групи в Налаштуваннях, двоколонкові Quick Settings. Увага до
деталей: майже все перелічене — це вже стан бази AOSP, тому наш реальний шар
це форма іконок, fallback-палітра й вибір профілю сітки.
Де межа з ресурсами Google — таблиця в [docs/UI.md](docs/UI.md); що саме
підтверджено іменами з бази — §8 того ж файла. Повний список ознак Pixel і
того, як саме вони відтворені, — [docs/PIXEL-PARITY.md](docs/PIXEL-PARITY.md).

Альтернативна самобутня тема (монохром, один акцент, hairline замість тіней)
збережена як варіант: [docs/UI-minimal.md](docs/UI-minimal.md).

## Сторінка проєкту

`site/index.html` — самодостатня сторінка: один файл, без збірки, без зовнішніх
скриптів і без інтернету. На ній живий макет чотирьох екранів, палітра якого
рахується від кольору-основи так само, як це робить Monet на пристрої.

Локально:

```bash
xdg-open site/index.html          # або просто перетягни файл у браузер
```

Публікація — GitHub Pages у режимі гілки (сторінка статична, тому Actions для
деплою не потрібні). Pages з гілки обслуговує лише корінь або `/docs`, а наш
сайт лежить у `site/`, тож його копія живе в корені ізольованої гілки
`gh-pages`. Після будь-якої зміни в `site/`:

```bash
build/scripts/publish-site.sh          # синхронізувати gh-pages і запушити
build/scripts/publish-site.sh --check  # лише показати різницю
```

Скрипт монтує `gh-pages` у тимчасове робоче дерево `.pages-worktree/`,
замінює її вміст на `site/` і робить пуш — основне робоче дерево не чіпається.
Воркфлоу `check-site` не пустять у `main` сторінку, яка не парситься або тягне
ресурси з чужого CDN.

Правило вмісту: на сайті не буває знімків «готової» системи, якої ще немає, і
жодних чужих шрифтів, логотипів чи найменувань. Макет підписаний як макет.

## Походження назви

**Tessera** — мозаїчний уламок, з якого складається зображення; тобто це
«піксель» іншим словом. Формат `< слово >OS` продовжує традицію вільних
дистрибутивів на кшталт LineageOS.

Свідомо **не** використовуємо: «Pixel», «Pixl», «Pixelike» та подібне.
`Pixel` — торгова марка Google, а існуючі проєкти на кшталт PixelOS і PixelExperience
вже займають цю нішу; схожа назва для прошивки — це ще й ризик довіри,
бо користувачі плутають, звідки вони беруть образ. TesseraOS — власна
ідентика, Material Design 3 як відкрита специфікація, а не копія чужого
інтерфейсу.
