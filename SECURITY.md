# Звіт про вразливість

## Чесний стан каналу

Приватного каналу ще **немає**. До цього файлу в репо висів
`security@tessera-os.example` — поштової домівки з такою назвою не існує,
листи туди не приходили нікому. Вимкнути це і сказати правду — перше, що
треба було зробити в цьому розділі.

Нині єдиний робочий шлях — **особисте повідомлення власнику репо на GitHub**
(`nothing12-glitch`). Жодних публічних деталей: ні issue, ні коментаря, ні
скриншота з вразливим місцем.

Власнику варто одним кліком увімкнути справжній канал:
`Settings → Code security and analysis → Private vulnerability reporting`.
Після цього сторінка `Security → Report a vulnerability` з'явиться, і тоді
саме вона стане правильним шляхом — цей файл треба буде оновити.

Обіцянок щодо строку відповіді не даємо: проєкт підтримує одна людина у вільний
час. Просимо натомість не публікувати деталі, доки є хоч якась ймовірність,
що їх хтось уже виправляє.

## Що для нас вразливість

- ключі підпису, токени чи паролі, які потрапили в git (навіть «тестові»);
- дозвіл, який наш модуль бере собі зайвий або тримає в `privileged` без
  потреби;
- allowlist привілеїв, що не збігається з маніфестом модуля — при
  `ro.control_privapp_permissions=enforce` це падаючий boot, а не дрібниця;
- наші скрипти, які виконують чужий ввід без ламок (особливо
  `install-on-vm.*`, `package-gapps.sh`, усе, що біжить з правами root);
- будь-що, що може знищити дані пристрою під час встановлення образу.

## Що не є вразливістю

- «образ не містить Google-сервісів» — це свідома межа продукту, див.
  `docs/GAPPS.md`;
- «дефект X є в базі» — вада LineageOS або Android належить їм: сюди ми її
  не приносимо, а несемо в upstream;
- запит на нову фічу, навіть дуже цікавий.
