# Як долучитися

TesseraOS — відкритий проєкт Apache-2.0: **LineageOS 22.2 + тема Material 3 +
два власні системні модулі** (вітальня першого запуску `apps/welcome` і
світловий край `apps/halo`). Решта — сток бази.

Перш ніж щось будувати, прочитай два правила, на яких тримається весь репо.

## Правило 1: стокове понад власне

Власний модуль у продукті появляється лише там, де **LineageOS не дає фічі
взагалі**. Усе, де існує сток-аналог, — сток. Це не теорія: сім наших
застосунків і власний лаунчер колись жили в образі, і всі їх прибрали, коли
виявилося, що база вміє те саме (`build/scripts/apps.list` нині має два
активні рядки). Тож PR із «ще одним нашим дзвінком» не пройде — і правильно.

## Правило 2: заява має збігатися з перевіркою

Ми два рази обпеклися на «модуль є в репо, а в образі мовчки не працює».
Тому: якщо чогось не перевіряли наживо — так і пиши. Формулювання
«не перевірено», «потрібен userdebug-образ», «лише статично» — це не
зауваження, а частина стилю. Публічні обіцянки microG у документії вже
доводилося прибирати двічі.

## Карта репо

| Шар | Що тут |
|---|---|
| `overlay/` | три RRO-оверлеї теми: `TesseraFrameworkTheme`, `TesseraSettingsTheme`, `TesseraIconShapeTheme` |
| `build/` | `tessera.mk` (product-конфіг, `TESSERA_VERSION`) і `build/scripts/` — усе, що реально щось робить |
| `apps/` | `welcome`, `halo` — окремі Gradle-проєкти, Kotlin + Compose + Material 3 |
| `manifest/`, `config/` | маніфест дерева й конфіги (зокрема профіль сервісів) |
| `brand/` | айдентика: логотип, шрифт, палітра |
| `site/`, `docs/` | сайт Pages і документація |
| `dist/` | локальні збірки пакунків; у git не потрапляє |

## Реєстр застосунків — єдине місце правди

`build/scripts/apps.list`, стовпчики: `тека|модуль|package|файл|роль`.
Роль — `-` (звичайний APK з іконкою) або `HOME`/`SETUP_WIZARD` (системний
майстер, без іконки). Його читають `prepare-app.sh`,
`check-app-integration.sh`, матриця CI, `make-vm-bundle.sh`,
`install-on-vm.sh` і `install-on-vm.ps1`. Порожній реєстр і реєстр з
одним рядком — легальні стани pipeline, тож закоментувати рядок безпечніше,
ніж щось видаляти.

Новий власний модуль = **два** рядки: активний рядок у `apps.list` і
`PRODUCT_PACKAGES += Модуль` у `build/tessera.mk`. Один без другого — і
обидва ловить `check-app-integration.sh`.

## Гаранті, які вже рятували CI

Правило, яке можна порушити, має жити в одному скрипті, а не в трьох місцях:

- `build/scripts/check-apk-manifest.sh` — які категорії має оголошувати APK
  за його роллю. Кличуть `prepare-app.sh` і job `apk` у
  `.github/workflows/build-apps.yml`. Подвоєння цього правила колись ломало
  білд: коли вітальня стала майстром, workflow досі вимагав іконку в кожного
  APK.
- `build/scripts/check-app-integration.sh` — `privileged: true` без рядка в
  дозвільному списку і без нього в `PRODUCT_PACKAGES` = падіння. Образ тримає
  `ro.control_privapp_permissions=enforce`, тож без allowlist boot не
  сходиться.
- `build/scripts/check-build-refs.sh` — чи справді існують файли бази, на які
  ми посилаємось, і чи не посилається документія на мертві шляхи в нашому
  репо.
- `build/scripts/check-overlay-names.sh`, `check-brand.sh`,
  `brand-font-check.js` — імена пакетів оверлеїв й айдентика.

Прогон локально, без образу:

```bash
bash build/scripts/check-app-integration.sh
bash build/scripts/check-build-refs.sh
bash build/scripts/check-overlay-names.sh
```

## Чотири шляхи внеску

### 1. Тема (найдешевший, ~20 хвилин)

1. Форк, гілка `theme/<акцент>`.
2. Правка в `overlay/themes/Tessera*Theme/res/values*/colors.xml`.
3. Перевірка без образу: `bash build/scripts/build-themes.sh`, потім
   `adb install -r overlay/out/TesseraFrameworkTheme.apk` на будь-якому
   Android 12+ і `adb shell cmd overlay enable os.tessera.theme.framework`.
4. PR із двома скріншотами — темна **і** світла тема — і контраст-перевіркою:
   `on*` на поверхні не нижче 4.5:1.

Правила MD3: тональні поверхні замість інверсії, радіуси з сітки 8/12/16/28,
без «скляних» ефектів. Копії зовнішності чужих оболонок не приймаємо.

### 2. Документація і відтворюваність збірки

Найцінніше на ранній стадії — пройти інструкцією на чистій машині й написати,
що не збіглося. Див. `docs/BUILD.md`, `docs/VM-INSTALL.md`, `docs/EMULATOR.md`.
Якщо правив текст, що обіцяє поведінку образу, — переконайся, що образ це
робить; інакше познач «не перевірено».

### 3. Пристрої

Порт на телефон — це device tree. Якщо LineageOS уже підтримує твій пристрій,
достатньо `local_manifests` + наш `build/tessera.mk`. Каталог
`devices/<codename>/` поки порожній: ціль реальна, але роботу не починали,
тож очікуємо обговорення в issue перед першим PR.

### 4. Модулі

`apps/<назва>/` — Kotlin + Compose + Material 3, динамічна палітра, підтримка
доступності, нові залежності лише через обговорення. Дві вимоги, специфічні
для нас:

- збірка локально або в CI: `gradle --no-daemon :app:testDebugUnitTest
  :app:assembleDebug` у теці модуля (Gradle 8.14.3 ставиться окремо,
  wrapper-jar у репо немає спеціально — бінарники забороняє політика);
- системний модуль, а не «застосунок з іконкою», якщо він має бути частиною
  першого запуску: тоді `CATEGORY_SETUP_WIZARD` без `CATEGORY_LAUNCHER`,
  `privileged: true` і рядок у дозвільному списку. Саме так зроблено
  вітальню — див. `apps/welcome/README.md`.

## Стиль комітів

Українською, формат «шар: що й чому», без префіксів `feat:`/`fix:` — так
виглядає вся історія: `CI: правило про LAUNCHER тепер в одному скрипті, а не
двох`. Один PR — один шар; правки в `overlay/**` не змішуємо зі змінами в
`build/**`.

CI, який має бути зеленим: `no-proprietary-blobs` і `build-refs`
(`policy.yml`), `discover` + матриця `apk` (`build-apps.yml`), `rro`
(`build-themes.yml`), `check` (`check-site.yml`). Job `rom` запускається
тільки за розкладом, бо справжня збірка образу вимогла б повного дерева
LineageOS.

## Чого викладати не можна

- власницьких ресурсів Google: бібліотек, іконок чужих застосунків, шпалер і
  звуків з прошивок, анімації перезавантаження — `policy.yml` блокує
  `*.so *.apk *.jar *.aar *.img *.zip` і шукає власницькі назви;
- ключів: `*.pk8`, `*.pem`, `*.keystore`, `build/testkey/*.jks`, `secrets/`,
  `.env` — ніколи, навіть «тестових»;
- справжніх токенів у скриптах і в прикладах документації.

## Вразливості й гарантії

Про приватний звіт про вразливість — `SECURITY.md`. Коротко: не відкривай
публічного issue з деталями. Прошивка пристрою може знищити дані: резервна
копія й розблокований bootloader лише з твоєї волі, гарантій проєкт не дає.
