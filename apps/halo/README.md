# Tessera Halo — світловий край екрана

Концепт прийшов із новин 2026 року про **Pixel Glow**: у Android 17 Google
показує функцію, де телефон «світить» на сповіщення, батарею та ліхтарик —
фізично, діодами під задньою панеллю Pixel 11. У LineageOS 22.2 (і в
більшості телефонів) апаратного індикатора немає взагалі, а програмного
замінника база не дає: `Settings → Сповіщення → Індикатор` існує лише тоді,
коли залізо вміє діод.

Tessera Halo — те саме призначення, реалізоване на склі: смуга світла по
периметру екрана, забарвлена в акцент Monet (те, що й тема TesseraOS) або в
колір самого сповіщення.

## Як це влаштоване

| частина | роль | чому саме так |
|---|---|---|
| `HaloListenerService` | джерело подій (`onNotificationPosted`/`onNotificationRemoved`) | `NotificationListenerService` система тримає живим сама, тому власний foreground-сервіс не потрібен |
| `HaloOverlay` | вікно `TYPE_APPLICATION_OVERLAY` на весь екран | вікно створюється **тільки на час світла** і прибирається по завершенні анімації |
| `HaloGlowView` | малює край: широка напівпрозора обвідка + вузьке яскраве ядро | дві обвідки дають відчуття світла замість «рамки» |
| `logic/HaloPlan` | чи світити | чисті правила, накриті юніт-тестами |
| `logic/HaloMotion` | криві анімації | те саме число живе й у превʼю на екрані |
| `logic/ColorBloom` | домінантний колір із пікселів | математика без Android-класів → тестується на JVM |
| `HaloSettingsActivity` | налаштування, дозволи, тест | жодного рішення про світло без перечитаних дозволів |

Візерунки: **Хвиля** (дві смуги біжать периметром, `DashPathEffect` з
анімованою фазою), **Пульс** (край дихає), **Суцільно** (рівне світло).
Усі три — один і той самий path по округленому прямокутнику, тому на будь-якій
роздільності виглядає однаково.

## Що перевірено наживо

Прогін 2026-10-25 на емуляторі Android 15 (AVD `TesseraVM`, 1080×2400, темна
тема). Знімки — у робочому каталогі `.scratch/shots/`, вони не в git.

| перевірка | результат | знімок |
|---|---|---|
| екран налаштувань рендериться, обидва дозволи — «Видано» | так | `52-halo-settings-dark.png` |
| візерунок «Хвиля»: смуги біжать периметром | так — на 0,5 с освітлено лівий і правий краї, верх і низ ще ні | `53-halo-edge-wave-dark.png` |
| світло згасає саме, без зайвого вікна | так — на 1,3 с лишається ледь помітний слід, далі зникає | `54-halo-edge-late-dark.png` |
| візерунок «Суцільно»: рівний периметр по всіх чотирьох сторонах | так | `55-halo-edge-solid-dark.png` |
| вікно живе рівно стільки, скільки налаштували | `logcat`: `WindowManager` створює `type = 2038` і знімає його після анімації | — |
| налаштування переживають перезапуск | `shared_prefs/tessera_halo.xml`: `pattern=SOLID`, `duration_ms=2400`, `intensity=0.85`, `last_color=#84A9F6` (Monet-акцент теми) | — |
| «Колір світла = Акцент Monet» бере колір системи, а не власну константу | так: збережений `last_color` збігається з `system_accent1_400` цієї теми | `55-halo-edge-solid-dark.png` |

Одне обмеження вишло з самої перевірки, і воно варте того, щоб його записати:
для вікна з `FLAG_NOT_TOUCHABLE` платформа зрізає `alpha` з 1.00 до 0.80
(пряме застереження у `logcat` від `WindowManager`). Тобто наживо край трохи
тьмяніший, ніж у превʼю на екрані налаштувань. Прибирати
`FLAG_NOT_TOUCHABLE` не будемо: без нього overlay перехопив би кожен дотик.

## Чого цей застосунок НЕ робить

Це той розділ, який робить функцію чесною. Усе перелічене нижче — не «поки
не встигли», а межа того, що дозволяє публічний API без системного ключа:

- **не світиться, коли екран вимкнений.** Вікно overlay система показує лише
  на ввімкненому дисплеї. Справжній AOD — окрема апаратна здатність, а не те,
  що можна домалювати зі звичайного застосунку.
- **не має діода й не імітує задню панель.** Це світло на склі, а не
  випромінювання ззаду телефону — на відміну від справжнього Pixel Glow.
- **не перемикає «Не турбувати» й не змінює гучність.** Він лише читає
  `zen_mode`, щоб мовчати разом із системою.
- **не читає текст сповіщень.** З обʼєкта беруться package, пріоритет,
  категорія, flags і колір; сам `extras` з текстом не зачіпається й нікуди не
  надсилається.
- **не знає важливості каналу чужого застосунку.** `NotificationChannel`
  привʼязаний до пакета, тому замість нього — `notification.priority`. Через
  це «лише помітні» іноді не світиться на те, що система все одно показала б
  heads-up.
- **не світить без двох дозволів.** `SYSTEM_ALERT_WINDOW` і доступ до
  сповіщень видає лише людина в Налаштуваннях; без них застосунок не робить
  нічого й чесно пише про це на своєму екрані.
- **не є системним майстром і нічого не замінює.** Це одне вікно-оверлей над
  екраном на 2–6 секунд світла, а не сервіс рівня `signature|privileged`:
  модуль `presigned`, платформного ключа немає.

## Інтеграція в образ

Рядок `halo|TesseraHalo|os.tessera.halo|tessera-halo-debug|-` у
`build/scripts/apps.list` + `PRODUCT_PACKAGES += TesseraHalo` у
`build/tessera.mk`. Обидва кроки статично звіряє
`build/scripts/check-app-integration.sh`; `Android.bp` — `android_app_import`
з `presigned: true`, тому apk у git не лежить (політика `policy.yml`).

Останній стовпчик реєстру — прочерк: Halo не потребує категорії на кшталт
`HOME` чи `SETUP_WIZARD`. Його «категорія» — це дві ролі в Налаштуваннях, а
їх статично не перевірив `aapt2`, тому вони перевіряються наживо.

## Збірка й установка

```bash
# на білд-хості (WSL2/Ubuntu):
cd apps/halo && gradle :app:assembleDebug :app:testDebugUnitTest

# на пристрій:
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell pm grant os.tessera.halo android.permission.POST_NOTIFICATIONS
adb shell appops set os.tessera.halo SYSTEM_ALERT_WINDOW allow
adb shell cmd notification allow_listener os.tessera.halo/os.tessera.halo.HaloListenerService
adb shell am start -n os.tessera.halo/.HaloSettingsActivity
```

Останній рядок — не `settings put secure enabled_notification_listeners`:
перевірено наживо, що запис лише нашого компонента система перезаписує
типовим списком слухачів, і край лишається вимкненим. `cmd notification
allow_listener` додає нас до наявного списку й не чіпає решту.

Після цього кнопка «Показати тестове сповіщення» на екрані засвітить край —
той самий шлях, яким іде звичайне сповіщення з будь-якого застосунку.
