# Tessera Камера

Власна «Камера» на Kotlin + Compose Material 3: фото, відео зі звуком і
редактор (поворот, пропорція, яскравість, контраст). Стокову камеру Google у
образ покласти не можна — вона пропрієтарна (див.
[docs/PIXEL-PARITY.md](../../docs/PIXEL-PARITY.md) §3), а без неї список
можливостей «фотографувати й редагувати» був би обіцянкою.

У git немає жодного бінарника: ані `gradle-wrapper.jar`, ані APK. Іконка
застосунку й усі службові знаки (спалах три стани, зміна камери, поворот,
закриття, галочка) — наші векторні `res/drawable/ic_*.xml`.

## Архітектура

Два екрани й два `ViewModel`, розділені рівно по тому, що потребує вікна:

* `CameraActivity` + `capture/CameraRig` — знімання. `CameraRig` тримає
  `ProcessCameraProvider`, `ImageCapture`, `VideoCapture<Recorder>` і активне
  `Recording`; активність — дозвіл, поворот екрана й привʼязку use cases;
  `CameraViewModel` — лише те, що видно на екрані.
* `EditorActivity` + `render/ImageBake` — правка одного знімка; `EditorViewModel`
  перераховує превʼю, `ImageBake` декодує й пише JPEG.
* `logic/` — чистий Kotlin без `android.*`-імпорту, тож перевіряється юніт-тестом
  на JVM: `ImageTransform` (поворот, найбільший центральний прямокутник пропорції,
  матриця тону, масштаб превʼю), `MediaNames` (імена й теки знімків),
  `formatRecordingDuration` (`m:ss` / `h:mm:ss`).

Пʼять рішень, які варто знати, перш ніж правити цей застосунок:

**CameraX живе в активності, а не у `ViewModel`.** Provider привʼязаний до
життєвого циклу вікна: `ViewModel` переживає поворот і знищення активності, а
привʼязка — ні. Тож стан пристрою тримає `CameraRig` в активності, і на
`onDestroy` він викликає `release()`: без цього незавершений запис лишає в
MediaStore незакритий рядок.

**Порядок правок у редакторі фіксований: поворот → обрізання → тон.** Якби
обрізання рахувалося до повороту, «квадрат» після 90° давав би інший прямокутник,
і користувач бачив би на екрані не те, що збережеться у файлі. Тому й превʼю, і
збереження проходять через ту саму `ImageTransform.resultBounds`.

**Повзунки тону не перекоднують кадр.** Яскравість і контраст малюються
`ColorFilter`-м на готовому превʼю, а в 5×4-матрицю перетворюються лише в
момент збереження. Geometry (поворот/пропорція) — єдине, що змушує декодер
працювати повторно.

**Контраст множиться навколо сірого, а не нуля.** `out = (in − 127.5)·k + 127.5`:
інакше «−100% контрасту» робила б чорне полотно замість однотонного сірого.

**Збереження — це копія.** Оригінал не перезаписується: повнороздільний кадр
декодується ще раз (превʼю зменшене до 2000 px по довгій стороні) і кладе
`Pictures/Tessera/IMG_…jpg`. Оригінальні знімки при цьому йдуть у
`DCIM/Tessera`, відео — у `Movies/Tessera`, через `MediaStore` і без
`WRITE_EXTERNAL_STORAGE`.

**Камера необовʼязкова.** У маніфесті `camera.any`/`camera.front`/`camera` з
`required="false"`, тож APK ставиться й на VM без відеопристрою. Там екран не
падає, а показує «Камери немає»; те саме — замість збою на відмовлений дозвіл.

## Стан

| Можливість | Реалізовано | Примітка |
|---|---|---|
| Роль застосунку (`MAIN` + `LAUNCHER`) | ✅ | `AndroidManifest.xml` |
| Фото через `ImageCapture` | ✅ | `CAPTURE_MODE_MINIMIZE_LATENCY`, `DCIM/Tessera` |
| Відео через `VideoCapture` + мікрофон | ✅ | HD з фолбеком на SD; без дозволу на звук — пише німе відео й каже це |
| Спалах (вимкнено / авто / увімкнено) | ✅ | `ImageCapture.FLASH_MODE_*` |
| Ліхтарик під час запису | ✅ | `enableTorch`: у відео спалах неможливий, зате світить увесь запис |
| Перемикання камера ↔ фронтальна | ✅ | кнопка неактивна, якщо передньої в системі немає |
| Зум жестом | ✅ | `detectTransformGestures` + межі реальної камери з `zoomState` |
| Збереження без зайвого дозволу | ✅ | `MediaStore` + `RELATIVE_PATH` з `Environment.DIRECTORY_*` |
| Редактор: поворот на 90° | ✅ | `EditParams.quarterTurns`, нормалізація по колу |
| Редактор: пропорція | ✅ | як є / 1:1 / 3:4 / 16:9 — найбільший центральний прямокутник |
| Редактор: яскравість і контраст | ✅ | `ColorMatrix` навколо 127.5, повзунки −1…1 |
| «Скинути» й «Зберегти» | ✅ | копія в `Pictures/Tessera`; оригінал залишається як був |
| Превʼю останнього знімка в куті | ✅ | `contentResolver.loadThumbnail`, а не повний кадр |
| Пояснення замість збою | ✅ | «Камери немає», «Камера вимкнена», «Не вийшло зняти» — плашка, що сама зникає |
| Geo-теги, HDR, серійна зйомка, фільтри, переднє дзеркало, RAW | ⬜ | наступні інкременти |

## Чого це НЕ підтверджує

Жодного кадру з пристрою чи зібраного образу: на хості немає апаратного
прискорення для емулятора (див. [docs/EMULATOR.md](../../docs/EMULATOR.md)).
Верифіковано збіркою й тестом, а не живим залізом:

* `:app:assembleDebug` на Gradle 8.14.3 / AGP 8.9.0 / Kotlin 2.0.21;
* 18 юніт-тестів чистої логіки: 13 на геометрію та матрицю тону, 5 на імена
  файлів і лічильник запису;
* `aapt2 dump badging` підтверджує `os.tessera.camera`, категорію `LAUNCHER` і
  три необовʼязкові риси камери;
* `check-app-integration.sh` — `TesseraCamera` в `PRODUCT_PACKAGES`, `presigned`
  без `certificate`, apk поза git, `applicationId` збігається з реєстром.

Не перевірено на живому пристрої: якість превʼю на конкретному сенсорі, чи
`ImageCapture` вміщається в памʼять VM із 2 ГБ, чи `withAudioEnabled()`
отримує мікрофон у нашому образі.

## Збірка

### 1. Самостійно, через Gradle (розробка)

Wrapper-jar свідомо немає, тому запускаємо Gradle з уже встановленою
дистрибуцією: 8.14.3 або новіша, AGP 8.9.0, Kotlin 2.0.21:

```bash
cd apps/camera
# локальний шлях до Android SDK — цей файл не комітиться (.gitignore)
echo "sdk.dir=/шлях/до/Android/Sdk" > local.properties
gradle --console=plain :app:testDebugUnitTest :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. На емулятор чи пристрій
з образом бази: `gradle :app:installDebug`.

### 2. Всередині образу ROM

Модуль оголошений у [Android.bp](Android.bp): `android_app_import` з іменем
`TesseraCamera`, `presigned: true`, `system_ext_specific: true` →
`system_ext/app/TesseraCamera/`. В `PRODUCT_PACKAGES` його додає
`build/tessera.mk`.

`overrides` тут свідомо немає: у базі LineageOS 22.2 своя камера (Aperture)
живе окремим застосунком, а не системою, тому дві камери в образі — видимий
дубль без наслідків для системи, а не конфлікт ролей.

Застосунок готує й перевіряє той самий скрипт, що й інші наші застосунки:

```bash
build/scripts/prepare-app.sh camera        # зібрати Gradle-ом
build/scripts/check-app-integration.sh camera
```

Дозволи на VM видає `install-on-vm.ps1` / `install-on-vm.sh`: `CAMERA` і
`RECORD_AUDIO` — обидва runtime, без них екран показує пояснення, а не кадр.
