# Мінімальні вимоги

Опитування №2 (питання про «щоб підходило і для старих телефонів») — єдине, де
відповідь можна дати числом, а не бажанням. Тому всі цифри нижче **зняті
вимірюванням 2026-10-26** на цьому ноутбуці з Android-образами, які ми реально
запускали. Оцінки з документації бази позначені окремо.

## Спершу — чому «старий телефон» не виходить

Єдиний справжній старий апарат, який був під'єднаний до цього проєкту —
Samsung Galaxy J5 (2017), `SM-J530F`. Дані зняті з пристрою через ADB, тільки
читання, нічого на ньому не змінювалось:

| Поле | Значення | Чому це блок |
|---|---|---|
| ABI | `armeabi-v7a, armeabi` — arm64 **відсутній** | LineageOS 22.x збирається під arm64; образу для 32 бітів немає і не буде |
| Ядро Linux | 3.18.91 | Android 15 очікує 4.19/5.4+ |
| Рівень API | 28 (Android 9) | наших двох APK із `minSdk = 33` система просто не встановить |
| Оперативна пам'ять | `MemTotal` 1 860 040 kB ≈ 1,78 ГБ | |
| `/system` | 2,8 ГБ, вільно 79 МБ | навіть оверлеї теми нікуди покласти |
| Завантажувач | `ro.boot.flash.locked=1`, `verifiedbootstate=green` | без розблокування не флешиться нічого; на Samsung це незворотний тригер Knox |
| Стан збірки | `ro.build.type=user`, `ro.debuggable=0`, SELinux Enforcing | |

Чотири перші рядки — **незалежні** блокери: усунення одного не рятує. Висновок
чесний і неприємний: у буквалному прочитанні («поставити TesseraOS на старий
апарат») відповіді немає. Це не наша примха й не недопрацювання коду — образ
фізично не для такої апаратури.

## Рівень 1 · Користувач образу (телефон або ВМ)

| Вимога | Значення | Як підтверджено |
|---|---|---|
| Архітектура | arm64 (або x86_64 для VM) | вимога бази, не наша |
| Рівень Android | 13 / API 33 і новіше | виміряно: наші APK `compileSdk 35`, `minSdk 33`, `targetSdk 35` |
| Оперативна пам'ять | **3 ГБ** як робочий мінімум | ⚠️ виведено, а не виміряно на телефоні — пояснення нижче |
| Вільне місце в образі | 8+ ГБ у `/data`, 2+ ГБ у системному розділі | виміряно на J5 (79 МБ у `/system` = не стало б місця навіть темі) |
| Розблокований завантажувач | обов'язково | виміряно на J5: заблокований → установка неможлива в принципі |

**Межа, яку ми все ж бачили на цифрах.** Гостьова система з повним Android-образом
завантажувалася й працювала з `-memory 1536` (1,5 ГБ) на x86_64: образ стартував,
наш майстер першого запуску проходив усі кроки, другий модуль малював поверхню.
Тобто 1,5 ГБ — це **межа завантаження**, а не комфорт. «3 ГБ» як мінімум —
стратегічне рішення, а не результат вимірювання на залізі: жодного телефону з
нашим образом у проєкті ще не було.

## Рівень 2 · Віртуальна машина на цьому ноутбуці

Все виміряно 2026-10-26 на хості AMD Ryzen 5 7535HS (6 ядер / 12 потоків),
15,3 ГБ RAM, 259,6 ГБ вільних із 475,8 ГБ на системному диску.

| Що | Реальний розмір |
|---|---|
| Завантажений системний образ (`android-37.0 / google_apis_playstore / x86_64`) | 2,7 ГБ |
| Каталог AVD після завантаження та роботи | 6,3 ГБ |
| `qemu-system-x86_64-headless` у робочому наборі під час запуску | 2 554 МБ |
| Обгортка `emulator.exe` | 10 МБ |
| `git clone` цього репозиторію (`.git`) | 6,9 МБ |
| Робочий каталог репозиторію з `dist/` і преглядом | 1,0 ГБ |

Звідси практичне правило, яке вже один раз коштувало нам завислої machines:
**синхронізоване дерево в WSL (≈8 ГБ RAM) і запущений емулятор (≈2,5 ГБ) на 15,3
ГБ хоста не уживаються** — треба обирати, і перемикатися свідомо, а не тримати
обидва.

## Рівень 3 · Білд-бокс (тільки для тих, хто збирає образ)

Тут чесно: **на цьому хості образ ще не зібрано**. Дерево бази не синхронізоване
до кінця (`frameworks/base` відсутній), тож цифри нижче — оцінка, а не факт.

| Вимога | Значення | Статус |
|---|---|---|
| ОС | Linux (у нас WSL2 + Ubuntu 24.04) | перевірено: інструменти й JDK працюють |
| Місце під дерево | 250+ ГБ | оцінка з документації, не виміряно |
| RAM | 16–32 ГБ | оцінка з документації; наш хост має 15,3 ГБ — тож збірка образу тут **під питанням** |
| Час | 2–6 год чистої збірки | не виміряно |

## Скільки важає наш власний код

| Артефакт | Розмір |
|---|---|
| `TesseraWelcome.apk` (збірка debug) | 24,6 МБ |
| `TesseraHalo.apk` (збірка debug) | 24,3 МБ |
| Пакунок `v15.22.2.3` — лише тема, нуль APK | 17 КБ |
| Пакунок `v15.22.2.1` — сім APK + тема | 34,3 МБ |

Два по 24 МБ — це вага **debug-збірки** двох Compose-застосунків; вона не
перевірена на стисненні. Для системи, де таке живе в системному розділі, це
забагато, і це окреме завдання: release-збірка з увімкненим R8 ще не виміряна. Рядок наведено
саме тому, що «наші модулі легкі» без цифри звучало б як ще одна неперевірена
обіцянка.

## Як прочитати відповідь на опитування

- **А (обираємо).** «Легке» = не старий залізний телефон, а набір перемикачів на
  **сучасному** слабкому апараті з 3–4 ГБ RAM: живі шпалери, м'який край і
  анімації вимикаються одним прапорцем. Це в межах нашої бази й не вимагає
  другого проєкту.
- **Б (не робимо).** Окрема база для старих апаратів (LineageOS 17.1/18.1 для
  `j5y17lte` існують лише як неофіційні збірки) — це інший проєкт: інший парк
  заліза, окремий супровідник, і жодної спільної кодової бази з нашими модулями.
  TesseraOS цього не обіцяє.

## Чого цей документ не стверджує

- Жодного вимірювання продукту на телефоні — весь живий прогін ішов на
  емуляторі x86_64.
- «3 ГБ RAM» — рішення, а не вимірювання; виміряно лише 1,5 ГБ як межу
  завантаження чужого образу.
- Розміри release-пакунків наших двох модулів — не отримані.
- Вимоги до заліза для Halo (чи так само тримає яскравість краю на OLED-панелі
  з іншою частотою оновлення) — не перевірені.
