# Інтерфейс «як на Pixel» — що відтворено і де межа

Документує свідомий вибір: TesseraOS виглядає і поводиться як стоковий
Android на Pixel, але складений лише з відкритих механізмів бази. Це не
копія прошивки Pixel — копія неможлива в публічному репо з власними
бінарними ресурсами Google (деталі в §3 і [GAPPS.md](GAPPS.md)).

## 1. Правило

Беремо три речі, які не є чужою власністю:

1. **Геометрію** — сітка, радіуси, відступи, розмір іконок.
2. **Палітру** — динамічну (Monet), частина AOSP.
3. **Поведінку** — жести, док, шухляда застосунків.

Не беремо жодного ресурсу з прошивки Pixel: ні APK, ні зображень, ні
звуків, ні шрифтів, ні найменувань. Усе втілене нашим налаштуванням стабільної
бази або власним кодом на відкритій основі Apache-2.0.

## 2. Відтворення по пунктах

Стан: ✅ = у репо й підтверджено деревом бази або збіркою; 🖥 = остаточну
перевірку робимо на зібраному образі; 🧩 = власний код уже в репо і збирається,
але поведінку на екрані ще не бачили (потрібен пристрій/образ); ⬜ = потребує
власного коду, ще не зроблено.

| Ознака Pixel | Як відтворено у TesseraOS | Стан |
|---|---|---|
| Динамічна колірна тема з шпалер | палітра Monet у базі; наш RRO `TesseraFrameworkTheme` — лише fallback, активний за `persist.tessera.dynamic_color=0` | ✅ |
| Круглі adaptive-іконки | RRO `TesseraIconShapeTheme`: `config_useRoundIcon=true` + `config_icon_mask` (framework `core/res/res/values/config.xml:4526`, `:4626`) | ✅ 🖥 |
| Сітка домашнього екрана 5×6 | build-time підміна `res/xml/device_profiles.xml`: `canBeDefault` лишилося істинним лише для профілю `5_by_6` | ✅ 🖥 |
| Док із 5 слотів | той самий профіль `5_by_6`: `numHotseatIcons="5"`, `defaultLayoutId="@xml/default_workspace_5x6"` | ✅ 🖥 |
| Пошукова пігулка в доці | уже так у стоці Trebuchet | ✅ |
| Щільність іконки/підпису (іконка 56, підпис 12 sp, рядок 104) | той самий профіль `5_by_6`: `iconImageSize`, `iconTextSize`, `allAppsCellHeight` | ✅ 🖥 |
| Картки в Налаштуваннях, круглі контейнери іконок у списку | уже так у стоці (`Theme.DeviceDefault`) | ✅ |
| Quick Settings: 2 колонки, радіус панелі 28 dp | уже так у базі (`quick_settings_num_columns=2`, `qs_corner_radius=28dp`) | ✅ |
| Великий годинник на екрані блокування | вбудований вибір стилю годинника в стоці | ✅ |
| Рядок «дата + погода» вгорі (At a Glance) | власний лаунчер у `apps/launcher` (Compose + Material 3); оверлеєм недоступно. Дата — наша з `java.time`; рядок погоди чекає на джерело (власницький віджет Google не вставляємо) | 🧩 |
| Поведінка дока й жестів як на Pixel | власний лаунчер: док із 5 слотів без підписів, пошукова пігулка над ним, свайп угору → шухляда, свайп вниз → закрити. Перетягування, папки й віджети ще не зроблені | 🧩 |
| Екран блокування з розмиттям шпалер | власний оверлей SystemUI/AOD; стокова можливість є в базі, але її імена ще не підтверджені | ⬜ |

## 3. Що не може бути ідентичним і чому

| Ресурс Pixel | Чому ні |
|---|---|
| `com.google.android.apps.nexuslauncher` (Pixel Launcher) | пропрієтарний APK; поширення в репо = порушення ліцензії |
| Шпалери й звуки Pixel | авторські зображення й аудіо Google |
| Анімація завантаження й анімації розблокування | ресурси Google; у AOSP є власні |
| Product Sans / Google Sans | торговельні марки Google; набір шрифтів не вільний |
| Логотип «G», назва «Pixel» | торговельні марки; не використовуємо як ідентичність проєкту |
| Стрічка «At a Glance» з вмістом Google | потребує власницьких сервісів; можемо зробити лише власну стрічку |

Наслідок: «один в один» у сенсі «та сама картинка з тієї самої прошивки» —
неможливе. «Один в один» у сенсі «та сама геометрія, та сама динамічна
палітра, та сама поведінка» — досяжне, і саме цей варіант реалізуємо.

## 4. Чому сітка — build-time підміна, а не RRO

Спершу спробували RRO `os.tessera.theme.launchergrid` із `res/xml/device_profiles.xml`.
Збірка підтвердила, що так не виходить:

```
res/xml/device_profiles.xml:46: error: attribute deviceCategory
  (aka os.tessera.theme.launchergrid:deviceCategory) not found.
```

Причина: aapt2 линкує оверлей проти пакету самого оверлея, а атрибути
`launcher:*` належать цільовому застосунку. Локальна `attrs.xml`-заглушка
дала б інші id атрибутів — оверлей зібрався б і мовчки нічого не змінив (той
клас помилок, від якого захищає `build/scripts/check-overlay-names.sh`).

Тому сітка лежить у `overlay-packages/` і підключається як
`DEVICE_PACKAGE_OVERLAYS += vendor/tessera/os/overlay-packages`
([build/tessera.mk](../build/tessera.mk)). Змінні досі живі в базі:
`build/make/core/product.mk:120-121`. Кладка — шлях у цільовому репо:
`overlay-packages/packages/apps/Trebuchet/res/xml/device_profiles.xml`.

Ризик, який не знятий: якщо база збирається з примусовим RRO й не виводить
нашу теку з `PRODUCT_ENFORCE_RRO_EXCLUDED_OVERLAYS`
(`build/make/core/product.mk:124`), підміна не застосується. Це перевіряється
лише на зібраному образі, на білд-боксі: після першого завантаження домашній
екран має бути 5 стовпців на 6 рядків без будь-якого ручного вибору, а в
Налаштуваннях лаунчера вибрано «5 × 6» і 5 іконок дока.

## 5. Як це підтримувати

Файл сітки — копія бази, тож при переїзді на новішу гілку його треба
переотримати з upstream і повторити правку. Інваріант «рівно один дефолтний
профіль» перевіряє CI (`build/scripts/check-overlay-names.sh`, блок
`[build-overlay]`). Той самий тест для кожного файла в `overlay-packages/`:
такий шлях має існувати в цільовому репо бази, інакше підміна мовчки нічого
не змінює. Ті самі вимоги до нового рядка таблиці §2: або підтверджене
ім'я в дереві бази, або власний код.

## 6. Власний лаунчер (`apps/launcher`)

Рядки §2 із 🧩 — це код у `apps/launcher`: Kotlin + Compose Material 3,
палітра з Monet (`dynamicDark/LightColorScheme`), геометрія з профілю
`5_by_6` (`GridSpec.LARGE_PHONE`: 5×6, док 5, іконка 56 dp, підпис 12 sp,
 комірка шухляди 104 dp, проміжок 16 dp).

Що підтверджено збіркою (локально, Gradle 8.14.3 + AGP 8.9.0):

- `:app:assembleDebug` і `:app:testDebugUnitTest` проходять; 4 тести на
  заповнення сітки (`HomeLayoutTest`);
- у зібраному APK маніфест оголошує `HOME` + `DEFAULT` для
  `os.tessera.launcher.LauncherActivity`, `minSdkVersion` = 33;
- в APK немає жодних чужих ресурсів — іконки беруться з `PackageManager`
  під час запуску, тому їхня відсутність у файлі є перевіркою, а не
  припущенням.

Чого це НЕ підтверджує: ані рядки, ані відступи не бачили на екрані.
Composable без пристрою не перевіряється чесно, тому 🧩 лишається до першого
кадру з образу. Образ також ще не поставляє наш лаунчер: для цього потрібен
`android_app` у `Android.bp` і позиція в `system_ext/priv-app` — без бінарників
у git (докладно в [apps/launcher/README.md](../apps/launcher/README.md)).
